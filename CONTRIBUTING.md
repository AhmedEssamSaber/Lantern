# Contributing to Lantern

Thank you for your interest in contributing to Lantern!

## 1. Branch Naming

Use descriptive branch names:

- `feature/feature-name`
- `fix/bug-description`
- `docs/documentation-update`

## 2. Commit Messages

Follow the Conventional Commits format:

`type(scope): description`

Examples:

- `feat(cli): add task sorting`
- `fix(storage): handle empty task lists`
- `docs(usage): update usage guide`

## 3. Development Workflow

1. Update your local main branch.
2. Create a new branch for your change.
3. Implement your changes.
4. Test your changes.
5. Commit using Conventional Commits.
6. Push your branch to your fork.

## 4. Pull Requests

1. Open a Pull Request against the original Lantern repository.
2. Describe the changes clearly.
3. Link the related Issue.
4. Wait for review and address requested changes.
5. Merge only after approval.
